# 使用说明

## 1. 准备

- 使用 Windows 10/11 64 位电脑，安装 Google Chrome。
- 确认自己能在学校网站正常登录并具有场馆预约权限；校外访问以学校实际要求为准。
- 准备同行人姓名和学校统一认证账号（学号/工号），按学校要求填写。
- 运行前先通过系统设置校准电脑时间。界面内的任务时间均为北京时间。

把 Windows 运行包完整解压，双击 `NEUCourtBooking.exe`。无需安装 Python。首次打开预约浏览器会联网下载匹配的驱动，建议提前完成，不要等到放号瞬间才启动。

## 2. 填写任务

程序启动后不会自行预约，需要你设置并开始任务。

以下说明对应 **1.2.0-preview.2 预发布测试版**。从 [本版 Release](https://github.com/Oppie2333/neu-court-booking/releases/tag/v1.2.0-preview.2) 下载 `NEUCourtBooking-1.2.0-preview.2-windows-x64.zip`，校验值见附件 `SHA256SUMS.txt`。

本版将设置简化为预约日期、扫描窗口、打球窗口、可选场地编号和一个查询间隔。请逐项填写并核对；程序不会自行启动任务。

| 设置 | 含义 |
| --- | --- |
| 预约日期 | 本次要打球的日期，允许今天至未来 30 天内的一天，必须明确选择。程序不会自动延续到第二天。 |
| 扫描开始 / 扫描结束 | 填写预约日期当天的北京时间 `HH:MM`，结束必须晚于开始，不跨午夜；决定程序何时开始查场、何时停止新的提交。由你核对学校当前放号规则后填写，程序不内置统一的放号时刻。 |
| 打球最早开始 / 打球最晚结束 | 填写 `HH:MM`，结束必须晚于开始，不跨午夜，只考虑完整落在此范围内的场次。例如 `14:00–21:00` 表示不早于 14:00 开始、不晚于 21:00 结束，与扫描或付款时间无关。 |
| 场地编号（可选） | 例如 `10,8,12`，只考虑这三片场地，按输入顺序优先。留空表示所有场地均可。多片场地作为备选，依次处理，不会同时创建多份订单。 |
| 查询间隔（秒） | 使用一个固定间隔，可填 0.5–60 秒，推荐 `0.5` 秒；查询依次执行，繁忙时自动退避。 |
| 同行人 | 填写除本人外 1–5 位同行人的姓名及学校账号；不要填写密码。 |
| 自动勾选条款 | 默认关闭。只有本人阅读当前学校条款并授权后，才允许程序勾选。 |

### 扫描时间与打球时段怎么填

两组时间分别控制程序运行和要预约的场次。例如，扫描填 `12:25–12:45`、打球填 `14:00–21:00`，表示只在前一段时间查场，目标是后一段时间内的完整场次。此处只是填写示例，不代表学校固定在某个时间放号。

学校可能分别开放上午、下午和晚间的场次，也可能调整开放时间。请先核对当前学校公告与预约页面，再决定扫描窗口；程序不会根据星期推算免费、付费或放号时间。

免费与付费场次都会进入候选，**不设置价格优先级，也不再区分免费优先模式或等待秒数**。程序按学校实际场次筛选，要求完整落在打球窗口内、属于所选场地且学校显示可用。付费按学生价 15 元/小时估算，每场最多 **30 元**；当前常见场次为 1 小时或 2 小时，不另行限定时长。支付页金额异常或无法核验时暂停，最终付款仍由本人操作。界面无需另设预算。

### 场地编号怎么填

接受 1–12 号场地，多个编号可用逗号或空格分隔。

- 填 `10,8,12`：只考虑 10、8、12 号场地，并按这一顺序优先。
- 留空：任何场地均可。

每片场地都是同一次预约的备选。程序串行查询和提交，**生成免费或付费的任一场订单后，就停止继续扫描**，最多一份订单。

### 查询间隔怎么设置

“查询间隔（秒）”只需填写一个值，允许 **0.5–60 秒**的小数，推荐 **0.5 秒**，对应最多每秒 2 次查询。

该值是相邻两轮**开始查询的最小间隔**。上一轮没有结束时不会叠加请求，实际频率取决于网站响应速度；选择多片场地也不会产生并发请求。

网站繁忙时自动按 2、4、8 秒退避；如果你设置的间隔更长，则继续采用较慢值。开始前请核对任务摘要中的查询间隔。

该设置只影响查找可用场地的节奏，不改变异常弹窗的反复确认、同一场次的提交重试或支付流程。

## 3. 开始与登录

1. 核对预约日期、扫描窗口、打球窗口、场地编号、查询间隔和同行人信息。如需自动勾选条款，先选中相应选项，再点击“确认设置并开始”并确认任务摘要。任务开始后设置不可修改。
2. 在程序新开的 Chrome 中自行登录学校。用户名、密码和验证码只在学校网页填写。
3. 等待程序校验目标场馆、日期和页面。出现已准备或等待扫描开始的提示后，保留程序和浏览器窗口。
4. 如果开始前选中了“登录后阅读当前学校条款，并选择是否授权程序自动勾选”，登录后在助手弹出的条款窗口中阅读，点击“已阅读，同意本次自动勾选”；也可以选择“本次手动勾选”。授权只对本次任务有效，不会保存给下次使用。没有授权时，条款页出现后需要你本人勾选，程序再继续。

任务运行期间请保持电脑开机联网、插电、不休眠、不合盖。不要同时手工点击提交、切换场次或用另一个程序操作这份任务的浏览器；修改设置请先停止任务。系统关机、合盖和更新仍可能中断运行。

## 4. 预约与重试如何进行

程序先填写目标场次和同行人，再提交学校校验，进入条款页后点击“去支付”。这个按钮对免费场也存在，免费场点击后应直接生成预约结果。

学校预约和收银页面出现浏览器原生弹窗（`alert / confirm`）时，程序**不按文字内容筛选，全部点击“确认 / 确定”**。关闭后再次出现弹窗就继续确认，直到没有弹窗。此规则包含网络异常、繁忙、已有预约和未识别文字的原生弹窗。

弹窗关闭后，程序再检查服务器响应、当前表单和已有订单。只有明确返回失败、前一次请求已结束，而且仍为同一场次的同一表单时，才再次点击**同一场次**的“去支付”；重复流程直到核验到订单、场次已满、任务停止或到达扫描结束时间。弹窗显示“已有预约”时也会先关闭，再检查已有订单，不因此重新创建预约。

确认弹窗与重复下单是两件事。断网、HTTP 错误、响应丢失或关闭弹窗后仍不能判断结果时，订单可能已在学校生成，程序会先查已有订单；仍无法确认就暂停并提示你核对。条款变化和金额异常也会暂停。请不要在结果未知时马上重新启动下单。

自动确认学校网页弹窗不会代替助手中登录后的条款阅读授权，也不会替你确认微信或支付宝的钱包付款；这些操作仍由本人完成。

查询按你设置的固定间隔依次执行，推荐 0.5 秒；繁忙时退避 2 / 4 / 8 秒，个人设置更慢时采用较慢值。具体含义见上文“查询间隔怎么设置”。

## 5. 看懂结果

| 程序提示 | 你需要做什么 |
| --- | --- |
| 等待登录 / 登录失效 | 在独立 Chrome 学校页面自行登录，按界面提示继续。 |
| 等待扫描开始 / 已准备 | 保留程序和浏览器，等待指定日期时间。 |
| 正在确认学校提示 / 重试同一场次 | 等待程序处理，不要同时手工提交。 |
| 需要勾选条款 | 本人阅读学校条款；如同意，在网页勾选。 |
| 免费预约已确认（`CONFIRMED`） | 程序已核对目标免费订单，仍建议在学校“我的”中查看有效预约。 |
| 付款窗口已显示（`PENDING_PAYMENT`） | 程序已识别付款二维码，尚未付款。核对金额和订单，在微信/支付宝中本人完成付款，并回学校核验。 |
| 支付需核对（`PAYMENT_REVIEW`） | 可能已有待支付订单，请在学校“我的”中查看并本人继续付款。 |
| 订单待核验（`ORDER_CREATED`） | 已到订单页，但内容或状态尚未完整确认，需本人核对。 |
| 需要核对 / 提交结果未知 | 先查学校“我的”中的已有订单，确认后再决定下一步。 |
| 已停止 / 已截止 | 不再进行新的提交；已在学校创建的订单仍需本人处理。 |

付费场会核对学校页面金额，处理学校支付页中可识别的方式选择和“申请支付”按钮，尝试打开并核验付款二维码。只点击按钮或跳转页面不会记为付款窗口已显示。登录支付账号、输入密码、扫码及最终付款均由本人完成。

本版尚未完成真实学校支付全流程验证。如果二维码或页面无法识别，程序会提示核对；请在学校“我的”中查看已有订单，再根据提示继续本人付款。不要为了重新打开付款页再次创建预约。

## 6. 停止与再次使用

点击“停止任务”可结束任务，正在进行的页面操作可能需要几秒才能返回，随后关闭助手启动的浏览器。关闭助手窗口也会请求停止；停止前请先核对或处理待支付订单，已有学校订单不会被自动取消。

再次预约需要重新设置明确的日期并开始任务。保存的设置不会自动启动预约，也不会每天定时运行。

## 7. 常见问题

**双击无法运行**：先确认解压完整、系统为 Windows 10/11 64 位，并保留运行包内的全部文件。程序未做数字签名时，Windows 可能显示发布者未知；请核对发布来源与发布页校验值，再自行决定是否运行。

**浏览器打不开或首次等待很久**：确认 Chrome 已安装，网络能访问学校和驱动下载服务。先关闭本程序后重新打开；不要下载参考仓库里来源不明的旧驱动来替换。

**页面日期不符或提示规则变化**：程序会暂停。检查学校实际放号规则和所选日期；不要通过修改网页绕过校验。

**已经出现待支付，程序却没有报成功**：这是正常区分。付费订单需要你付款，最终以学校显示的有效订单为准。

**没有抢到场**：网站拥堵、登录失效、无可用场次或页面调整都可能导致失败，程序不能保证成功率。

本版为预发布测试版：103 项自动测试、本地 Chrome 模拟流程及运行包界面、Chrome `about:blank` 启动检查已通过。模拟覆盖不同文字和空弹窗的连续确认、明确失败后的重试、未知结果的订单核验与付款二维码交接。尚未完成真实学校预约和支付全流程、真实高峰成功率及另一台干净电脑的兼容性验证，不能保证抢到场地。

## 8. 本地数据与反馈

本地设置与运行资料位于 `%LOCALAPPDATA%\NEUCourtBooking`，可点击“打开本机数据目录”查看。配置含同行人姓名、学校账号；日志和订单状态也可能含私人内容。公开版不自动保存登录后的网页源码或截图；你自己截取的图片也请先遮盖个人信息。不要将本机数据目录直接发给他人或上传 GitHub。

反馈时提供软件版本、Windows/Chrome 版本、问题发生的北京时间及已遮盖个人信息的报错。不要发送账号密码、验证码、cookie、支付码或完整订单页面。分享软件请使用原始运行包，不要把自己的数据目录一并打包。
